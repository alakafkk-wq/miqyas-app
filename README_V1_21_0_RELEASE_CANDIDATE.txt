MIQYAS v1.21.0 — Release Candidate 2
====================================

هذه حزمة مرشح إصدار جاهزة لرفع ملفات الواجهة بعد تنفيذ خطوات Supabase أدناه. لا تعتبر منشورة بمجرد فك الضغط أو رفع ملفات الواجهة. لم يتم الاتصال بمشروع Supabase الإنتاجي من هذه الجلسة، ولذلك لم يتم تنفيذ SQL أو نشر Edge Function أو اختبار البريد/الصلاحيات على الإنتاج.

المحتويات والتعديلات
--------------------
1) لوحة مالك المنصة: مؤشرات المنشآت والاشتراكات والفروع وتقييمات VOC، مع تقارير Excel وفلاتر الفترة.
2) إدارة مستخدمي المنشأة: تظهر فقط لحساب role=owner. إرسال دعوة بريدية عبر Edge Function آمنة، مع الأدوار manager/supervisor/user، ومنع إضافة مالك آخر.
3) التحقق الخادمي من مالك المنشأة والاشتراك الساري ونوع الباقة وحد max_users قبل إرسال الدعوة.
4) إنشاء مستخدم Auth عبر inviteUserByEmail من الخادم فقط. مفتاح service role لا يظهر في الواجهة.
5) سياسة قراءة أعضاء المنشأة لمالكها فقط عبر دالة SECURITY DEFINER.
6) تصدير Excel للمشتركين وعمليات الاشتراك وحركة المستخدمين.
7) عرض التواريخ بالتقويم الميلادي مع locale عربي.
8) إزالة خدمة المتسوق السري من الواجهة مع الاحتفاظ بالسجلات التاريخية.
9) الإبقاء على تكامل الدفع الحالي كما هو دون تعديل.

خطوات النشر المطلوبة بالترتيب
-----------------------------
أولاً — نسخة احتياطية
- خذ نسخة احتياطية من قاعدة البيانات واحتفظ بنسخة v1.20.7 المنشورة للرجوع.

ثانياً — SQL
- افتح Supabase Dashboard > SQL Editor.
- راجع ثم نفّذ الملف MIQYAS_V1_21_0_OWNER_MEMBERS.sql مرة واحدة.
- تحقق أن نتيجة الاستعلام الأخيرة تعرض policy باسم:
  miqyas owners read organization members
- لا تنفذ ملفات SQL القديمة كلها مرة أخرى؛ هذا التحديث يضيف migration محدداً فقط.

ثالثاً — Edge Function
- من جذر المشروع نفّذ:
  supabase functions deploy owner-manage-members
- تأكد من توفر أسرار المشروع القياسية في Supabase Functions:
  SUPABASE_URL
  SUPABASE_ANON_KEY
  SUPABASE_SERVICE_ROLE_KEY
- إذا لم تكن الأسرار القياسية مضبوطة، اضبطها من إعدادات Supabase Functions/Secrets. لا تضع service role key في config.js أو app.js أو GitHub Pages.
- لا يلزم Google API key لهذه الوظيفة.
- راجع إعدادات Auth > URL Configuration وEmail Templates وتأكد من صحة Site URL وRedirect URLs حتى يصل رابط الدعوة للمستخدم.

رابعاً — ملفات الواجهة
- ارفع محتويات المجلد إلى استضافة الموقع مع الحفاظ على المسارات.
- لا ترفع مجلد supabase/functions كملفات واجهة؛ الوظيفة تنشر عبر Supabase CLI.
- تأكد أن config.js يحتوي فقط على Supabase URL وPublishable/Anon key العام.

خامساً — اختبارات قبول قبل اعتماد النشر
1. تسجيل الدخول بحساب مالك منشأة تجريبية.
2. تأكد من ظهور إدارة المستخدمين للمالك فقط.
3. جرّب دعوة بريد غير مسجل، وتأكد من وصول رسالة الدعوة.
4. أكمل إنشاء كلمة المرور، وتأكد من ظهور المستخدم في organization_members بالدور المحدد.
5. جرّب من حساب manager ثم supervisor ثم user: يجب ألا تظهر لوحة الدعوات، ويجب أن ترفض الوظيفة الطلب المباشر بـ 403.
6. اختبر الحد: basic/ecom_basic = 3، professional/ecom_professional = 10، enterprise/ecom_enterprise = 30. يجب أن يرفض الخادم الزيادة.
7. اختبر منشأة باشتراك منتهي: يجب أن يرفض الخادم الدعوة.
8. اختبر عدم تكرار بريد مسجل مسبقاً، وعدم بقاء Auth user orphan إذا فشل إدخال العضوية.
9. راجع لوحة مدير المنصة والتقارير والفلاتر وتصدير ملفات Excel.
10. اختبر طلب الدفع الإلكتروني الحالي وسيناريو التحويل البنكي والفاتورة البريدية؛ لم يتم تغيير مزود الدفع.
11. اختبر المتاجر الإلكترونية ولوحة الفروع والتقييمات وسجل الحركة والتواريخ الميلادية على أجهزة الجوال.

ملاحظات مهمة
-------------
- هذه الحزمة مرشح إصدار (Release Candidate)، وليست شهادة نجاح اختبارات الإنتاج.
- إدارة المستخدمين تتيح الدعوة والإضافة فقط في هذه النسخة؛ لا تتضمن حذف عضو أو تغيير صلاحياته بعد الإضافة.
- جدول organization_members الحالي لا يحتوي بريداً إلكترونياً موثوقاً في البيانات التي فحصناها؛ لذلك تعرض القائمة معرف المستخدم المختصر والدور وتاريخ الإضافة، ولا تعرض بريداً غير موثق.
- الإيرادات في لوحة مدير المنصة تعتمد على سجلات subscription_payment_requests ذات الحالة paid أو approved؛ ينبغي مطابقة تعريف الحالات مع إجراءات التحصيل الفعلية قبل اعتماد الرقم محاسبياً.
- بيانات المتاجر الإلكترونية لا تدخل حالياً في جدول متابعة الفروع. صفحات تقارير المتجر الحالية تبقى ضمن مساحة المنشأة.
- لم يتم تشغيل SQL على الإنتاج أو نشر الوظيفة أو الواجهة من هذه الجلسة. لا تعتمد الإصدار نهائياً قبل اجتياز اختبارات القبول أعلاه.
