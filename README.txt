مقياس MIQYAS Cloud - الإصدار 1.4

قبل التشغيل:
1) افتح config.js.
2) ضع Publishable Key الذي يبدأ بـ sb_publishable_ مكان PASTE_YOUR_SB_PUBLISHABLE_KEY_HERE.
3) لا تضع Secret Key أو service_role في هذا الملف.
4) ارفع مجلد miqyas_cloud إلى استضافة HTTPS ثابتة. يمكن استخدام استضافة مجانية تدعم المواقع الثابتة.
5) افتح الرابط من الهاتف.

الميزات:
- تسجيل حساب بالبريد وكلمة المرور عبر Supabase Auth.
- تسجيل الدخول والخروج.
- إنشاء مساحة منشأة عبر RPC create_organization.
- إضافة الفروع وحفظها في Supabase.
- إضافة تقييمات VOC والمتسوق السري والتقييم الداخلي.
- قراءة بيانات المنشأة والفروع والتقييمات وفق سياسات RLS.
- واجهة عربية متجاوبة وPWA.

إعدادات Supabase:
- Project URL مضبوط مسبقاً في config.js.
- يلزم إدخال Publishable Key فقط.
- تأكيد البريد الإلكتروني مفعل: بعد التسجيل تحقق من البريد، ثم سجل الدخول.
- في Authentication > URL Configuration أضف رابط موقعك ضمن Site URL وRedirect URLs بعد نشره.

ملاحظات أمنية مهمة:
- المفتاح الموجود في المتصفح هو Publishable Key فقط؛ لا تستخدم مفاتيح Secret أو service_role في الواجهة.
- سياسات RLS الحالية تتيح لأعضاء المنشأة قراءة بياناتها، والمدير/المالك إدارة الفروع. يجب إجراء اختبار عزل بحسابين مختلفين قبل استخدام بيانات حقيقية.
- هذه نسخة تشغيل أولى؛ لا تشمل دعوات الموظفين وإدارة الأدوار من الواجهة أو الدفع الإلكتروني أو استعادة كلمة المرور.
- النتيجة الحالية للتقييم تحتسب نسبة الإيجابي من مجموع الإيجابي والمحايد والسلبي. أوزان جودة الفروع المتقدمة ستضاف لاحقاً.
- بيانات الحسابات والمنشآت والفروع والتقييمات تحفظ في Supabase، أما ملفات الواجهة فتستضاف على خدمة استضافة ثابتة.


إضافة تقييم العميل عبر QR (الإصدار 1.1):
1) افتح MIQYAS_PUBLIC_FEEDBACK.sql وانسخ محتواه كاملاً إلى Supabase SQL Editor ثم Run.
2) بعد نجاح التنفيذ، ارفع الملفات المحدّثة كلها إلى مستودع GitHub نفسه مع استبدال الملفات القديمة.
3) افتح مقياس وسجّل الدخول. سيظهر زر "QR التقييم" بجانب كل فرع.
4) افتح الرمز واطبع QR أو انسخ الرابط. العميل يفتح الرابط دون حساب ويختار راضٍ/محايد/غير راضٍ.
5) التقييمات العامة تحفظ في جدول customer_feedback. هذه النسخة تعرضها في صفحة العميل؛ يلزم تحديث لوحة المؤشرات لاحقاً لدمجها مع إحصاءات VOC.

تنبيه:
- نفّذ SQL قبل رفع الواجهة الجديدة؛ الواجهة تعتمد على public_token وRPC.
- لا تضع مفاتيح Secret أو service_role في ملفات الواجهة.
- نموذج QR أولي. قبل الاستخدام التجاري الواسع أضف حماية إساءة الاستخدام (مثل CAPTCHA / حدود معدل الطلبات) وسياسة خصوصية وإشعار موافقة مناسبين.
- التقييم العام منفصل عن quality_assessments حتى لا يكتب المستخدم المجهول في جدول التقييمات الداخلية.


إضافة نظام الاشتراكات (الإصدار 1.3):
1) ارفع ملفات الواجهة الأربعة app.js وindex.html وstyle.css وsw.js إلى GitHub.
2) افتح Supabase SQL Editor ونفّذ ملف MIQYAS_SUBSCRIPTIONS.sql.
3) أضف UID حساب مالك منصة مقياس في جدول platform_admins باستخدام السطر المعلّق في نهاية SQL.
4) أضف بيانات الحساب البنكي الرسمي في subscription_bank_settings بعد اعتمادها.
5) طلبات التحويل البنكي تظهر في لوحة إدارة الاشتراكات لحساب مالك المنصة، ويمكن اعتمادها أو رفضها.
6) لا يتم تقييد مساحة العمل الحالية عند عدم وجود اشتراك؛ تفعيل حدود الباقات والإيقاف الآلي مرحلة تالية بعد اختبار الاشتراكات.

الدفع الإلكتروني:
الواجهة تعرض خيار الدفع الإلكتروني على أنه بانتظار الربط. لا يتم تحصيل أي مبلغ إلكترونياً حالياً.
قبل تفعيل الدفع المباشر يجب اختيار مزود دفع مناسب للسعودية (مثل Moyasar أو HyperPay أو Tap)، وتهيئة مفاتيح Secret داخل Supabase Edge Functions فقط، مع إعداد Webhook موثوق للتحقق من الدفع. لا تضع أي مفتاح سري داخل config.js أو app.js.

تحديث مقياس 1.4:
1) نفّذ MIQYAS_V1_4_GOOGLE_MAPS.sql في Supabase SQL Editor.
2) ارفع الملفات app.js وindex.html وstyle.css وicon.svg وmanifest.webmanifest وsw.js إلى GitHub مع الاستبدال.
3) يظهر في بيانات الحساب البريد ومعرّف المستخدم واسم المنشأة وتاريخ التسجيل وعدد الفروع.
4) عند إضافة فرع يمكن إدخال رابط صفحة الفرع على Google Maps ويظهر زر لفتح صفحة الفرع.

6) حدّث رقم التواصل والبريد لاحقاً بعد تزويدنا بالبيانات المطلوبة.
