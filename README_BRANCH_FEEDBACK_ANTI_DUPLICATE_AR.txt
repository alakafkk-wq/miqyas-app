MIQYAS v1.21.5 – حماية تكرار تقييمات الفروع دون OTP

محتويات التحديث:
- إضافة حقل رقم الجوال في صفحة تقييم الفرع.
- إنشاء معرّف جهاز عشوائي محلياً.
- إرسال الطلب إلى Edge Function باسم branch-public-feedback.
- إنشاء HMAC للجوال والجهاز داخل الوظيفة الخادمية فقط.
- التحقق الذري من عدم تكرار الرقم أو الجهاز خلال 24 ساعة.
- لا يتم تعديل التقييمات القديمة أو مسار تقييم المتاجر الإلكترونية.

ترتيب النشر الآمن:
1) خذ نسخة احتياطية من قاعدة البيانات وملفات الموقع.
2) جهّز وظيفة Edge Function أولاً وانشرها بعد إضافة الأسرار، ثم نفّذ SQL. عند تنفيذ SQL تُغلق صلاحية دالة التقييم القديمة العامة؛ لذلك لا تنفّذ SQL قبل جاهزية الوظيفة والواجهة للنشر المتتابع.
3) أنشئ قيمة سرية عشوائية لا تقل عن 32 حرفاً، واحفظها باسم MIQYAS_FEEDBACK_HMAC_SECRET في Supabase Edge Function Secrets. لا تضعها في config.js ولا ترسلها لأحد.
4) انشر مجلد supabase/functions/branch-public-feedback كـ Edge Function بنفس الاسم. إذا كان النشر عبر CLI، استخدم: supabase functions deploy branch-public-feedback --no-verify-jwt
5) ارفع ملفات الموقع المحدثة من مجلد MIQYAS_v1_21_2_ADMIN_UPDATE إلى الاستضافة.
6) اختبر أول تقييم برقم وجهاز جديدين؛ يجب أن ينجح. أعد التقييم بنفس الرقم؛ يجب أن يرفض. جرّب رقمًا آخر من الجهاز نفسه؛ يجب أن يرفض. جرّب جهازاً ورقماً جديدين؛ يجب أن ينجح.
7) افحص تقرير VOC للتأكد من احتساب التقييمات المقبولة فقط.

ملاحظات مهمة:
- لا تنفذ حذفاً أو truncate لأي جدول.
- لا تحذف submit_public_feedback في هذه المرحلة؛ الواجهة الجديدة لا تستدعيها، لكن نغلق صلاحياتها بعد التحقق من عدم وجود عملاء أو روابط قديمة تعتمد عليها.
- يجب عدم مشاركة SUPABASE_SERVICE_ROLE_KEY أو MIQYAS_FEEDBACK_HMAC_SECRET.
- حماية الجهاز تعتمد على معرّف مخزن في المتصفح؛ مسح بيانات المتصفح أو استخدام جهاز آخر قد يتجاوز هذا العامل. لا يوجد تحقق من ملكية رقم الجوال لعدم استخدام OTP.
- الكود يحتاج اختباراً على مشروع Supabase قبل اعتباره منشوراً أو ناجحاً إنتاجياً.
